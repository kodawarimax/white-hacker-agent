# 🛡️ AI White Hacker Agent (`white-hacker`)

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Python: 3.8+](https://img.shields.io/badge/Python-3.8%2B-green.svg)](#)
[![Dependencies: Zero](https://img.shields.io/badge/Dependencies-Zero-brightgreen.svg)](#)

> **「悪い人に見つかる前に、自分のアプリの弱点を見つけて・直して・確かめる」**
> Claude Code / Codex / Cursor / Antigravity 対応の防衛特化型AIホワイトハッカーエージェント＆ローカル診断ツール

AIコーディング（バイブコーディング）で誰でも一瞬でWebアプリを作れるようになった一方、**「ログイン確認はあるけれど、URLの注文番号を1つ変えるだけで他人の注文が見えてしまう（アクセス制御の不備 / IDOR）」** といった弱点が残ったまま公開される事故が増えています。

このリポジトリは、**追加パッケージ不要（Python標準機能のみ）・API従量課金ゼロ**で、自分のアプリに弱点がないかを「調べる ➔ 試す ➔ 報告する ➔ 直してもう一度試す」の4ステップで点検できるスターターキットです。

---

## ✨ 特徴（なぜ初心者でも使いやすいのか？）

1. **準備は1行だけ（外部ライブラリのインストール不要）**
   Python 3 が入っていれば、面倒な設定や有料APIキーなしで今すぐ動きます。
2. **4人の専門AI担当（ロール）がチームで点検**
   - 🔍 **アクセス制御（IDOR）担当**: 他人の注文・個人情報・投稿が見えてしまわないか
   - 🔐 **ログイン・セッション担当**: 認証の抜けやトークン偽造の弱点がないか
   - 💉 **入力注入・XSS担当**: SQLインジェクション、コマンド注入、画面への不正プログラム混入（XSS）がないか
   - 🔑 **API・秘密鍵担当**: プログラム内にAPIキーやパスワードが直接書き込まれていないか
3. **「怪しい候補を並べて終わり」にしない（誤検知の自動除外）**
   すでに持ち主確認（`user_id == current_user.id`）や無害化（`DOMPurify`）が入っている箇所は自動で除外し、**本当に直すべき弱点だけを分かりやすい日本語レポート＋ブラウザ画面（`report.html`）**で出力します。
4. **「0件＝100%安全」の勘違いを防ぐ3つの確認視点**
   結果が0件だったときも、①最後まで終わったか（`run.json`）、②上限金額で止まっていないか、③どこまで調べたか（死角はないか）を自動で表示します。

## 🚀 1分で始める使い方

### Step 1: インストール（1行コマンド）

```bash
git clone https://github.com/kodawarimax/white-hacker-agent.git
cd white-hacker-agent
bash install.sh
```

### Step 2: まずは「3秒体験デモ」を動かしてみる（おすすめ！）

自分のアプリを用意する前に、**「他人の注文が見えてしまう弱点を見つけて、直して、0件になるまで」** を自動で体験できます：

```bash
python3 white_hacker_runner.py demo
```

### Step 3: 自分のアプリフォルダを調べる

```bash
# 自分のアプリのフォルダを指定して検査（quick / standard / deep）
python3 white_hacker_runner.py scan --target /path/to/your-app --mode standard

# 結果をターミナル＆ブラウザ（ビジュアル画面）で開く
python3 white_hacker_runner.py view --open
```

## 🤖 Claude Code / Codex / Antigravity から使う方法

`bash install.sh` を実行すると、お使いのAIエージェントに `white-hacker` が登録されます。
普段のチャット画面で以下のように話しかけるだけで使えます：

- 💬 **調べたいとき**:
  `「white-hacker でこのフォルダのセキュリティの弱点を調べて」`
- 💬 **見つけた弱点を直して確かめたいとき**:
  `「見つかった弱点の原因を直して、もう一度試して直ったか確かめて」`

---

## 📂 出力されるレポートの中身（`strix_runs/` 互換）

検査を実行すると、`strix_runs/run_YYYYMMDD_HHMMSS/` フォルダの中に以下のファイルが自動保存されます：

| ファイル名 | 内容 |
| :--- | :--- |
| `report.html` | **初心者向け！** ブラウザで開いて読めるビジュアル診断レポート |
| `summary.md` | 全体のまとめレポート（見つかった件数＋3つの確認視点） |
| `findings/WH-001.md` | 弱点1件ごとの詳細ファイル（何が起きるか・再現手順・直し方のコード例） |
| `vulnerabilities.json` | AIエージェントが読み取って自動修正するためのデータ一覧 |
| `run.json` | 最後まで終わったか（`completed` / `stopped`）と費用・検査範囲の記録 |

## ⚠️ 使うときの3つの大切なルール（必読）

1. **必ず「自分のアプリ」または「許可をもらった対象」だけに使うこと**
   友達のサイトや他人のWebサイトを許可なく調べることは法律違反（不正アクセス禁止法など）になります。このツールは安全のため、外部の無断URL（`https://...`）を指定すると自動でブロックする仕組みが入っています。
2. **本番環境ではなく、手元のパソコンやテスト環境（ステージング環境）で行うこと**
   実際のお客様が使っている本番データや本番パスワードを置いた場所ではなく、開発用・練習用の環境で動かしてください。
3. **「0件＝100点満点で絶対に安全」ではないことを覚えておくこと**
   「0件」は「今回調べた範囲では見つからなかった」という意味です。レポート末尾に出る **3つの視点（①最後まで終わったか、②上限で止まっていないか、③管理者目線など未検査の範囲はないか）** を必ず確認してください。
