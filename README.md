> **「組織全体の構造を理解し、100点満点でセキュリティを包括採点。弱点の発見・修正から『継続保守プログラム提案書』の作成までを一気通貫で標準化」**
> Claude Code / Codex / Cursor / Antigravity 対応の防衛特化型AIホワイトハッカー＆包括セキュリティ監査基盤

AIコーディング（バイブコーディング）で誰でも一瞬でWebアプリを作れるようになった一方、**「ログイン確認はあるけれど、URLの注文番号を1つ変えるだけで他人の注文が見えてしまう（アクセス制御の不備 / IDOR）」** といった弱点が残ったまま公開される事故が急増しています。

このリポジトリは、**追加パッケージ不要（Python標準機能のみ）・API従量課金ゼロ**で、組織・プロジェクト全体の構造（6大レイヤー・5つの信頼境界）を把握し、**100点満点の標準監査レポート**およびクライアント・経営層へそのまま提出できる**「サイバーセキュリティ継続保守プログラム提案書」**を自動生成するスターターキットです。

## 🏆 100点満点・6大領域の標準セキュリティ採点基準

単なるバグ一覧ではなく、組織・システムの全構造を以下の **6大監査領域（合計100点満点）** で決定論的に採点します：

| 監査領域（6大レイヤー） | 配点 | 主な検査・評価対象 |
| :--- | :---: | :--- |
| **① アクセス制御・業務ロジック・認可** | **25点** | 他人の注文・データ参照（IDOR/BOLA）、管理者エンドポイントの権限確認漏れ（RBAC） |
| **② 認証・セッション・ID統治** | **15点** | JWT署名検証の無効化（`verify=False` / `alg:none`）、Cookie属性（`HttpOnly`/`Secure`） |
| **③ 入力検証・インジェクション・XSS/SSRF防御** | **20点** | SQLインジェクション、OSコマンド注入（`shell=True`）、未サニタイズXSS、SSRF |
| **④ 秘密情報・データ保護・暗号化** | **15点** | APIキー・秘密鍵のコード埋め込み、`NEXT_PUBLIC_`/`VITE_` フロント露出、`.env` Git保護 |
| **⑤ インフラ・クラウド設定・CI/CD・サプライチェーン** | **15点** | CORS全面開放（`*`＋認証併用）、本番デバッグ有効化、ロックファイル・自動テスト有無 |
| **⑥ AIガバナンス・例外処理(Fail-Closed)・監査証跡** | **10点** | 外部入力の `eval`/`exec` 動的実行遮断、エラーの無言握り潰し（`except: pass`）防止 |

### 🚨 見せかけの高得点を防ぐ「致命的欠陥ハードキャップ制」
「秘密鍵が漏れているのに、他の項目が満点だから90点（合格）」という危険な錯覚（Security Theater）を防ぐため、以下の上限固定ルールを標準適用します：
- **`CRITICAL`（致命的弱点）が1件でも残存** ➔ 素点に関わらず **最高 49点（Grade D: 本番公開不可）** に強制固定
- **`HIGH`（IDOR・XSS・コマンド注入等）が残存** ➔ 素点に関わらず **最高 69点（Grade C: リリース前修正必須）** に強制固定
- **すべての重大リスクを解消後** ➔ **85〜100点（Grade A / Grade S: 本番リリース可・継続保守フェーズ）**

## 🚀 1分で始める使い方

### Step 1: インストール（1行コマンド）

```bash
git clone https://github.com/kodawarimax/white-hacker-agent.git
cd white-hacker-agent
bash install.sh
```

### Step 2: まずは「3秒体験デモ（69点 ➔ 修正 ➔ 100点）」を動かしてみる

自分のアプリを用意する前に、**「他人の注文が見えてしまう弱点を見つけて（69点 / Grade C）、直して、もう一度検査して 100点（Grade S）になるまで」** を自動で体験できます：

```bash
python3 white_hacker_runner.py demo
```

### Step 3: 組織・自分のアプリフォルダを包括監査する

```bash
# 対象フォルダを指定して100点満点監査＋保守提案書を生成（quick / standard / deep）
python3 white_hacker_runner.py scan --target /path/to/your-app --mode standard

# 結果をターミナル＆ブラウザ（ビジュアル監査ダッシュボード）で開く
python3 white_hacker_runner.py view --open
```

## 📂 出力される標準監査レポート一式（`strix_runs/`）

検査を実行すると、`strix_runs/run_YYYYMMDD_HHMMSS/` フォルダの中に以下のファイルが自動保存されます：

| ファイル名 | 内容 |
| :--- | :--- |
| **`report.html`** | **経営層・クライアント提示用！** 100点満点ゲージ・6領域グラフ・組織構造マップ・保守プラン表付きHTMLダッシュボード |
| **`maintenance_proposal.md`** | **営業・提案用！** 監査結果に基づき自動生成される「サイバーセキュリティ継続保守プログラム提案書（3フェーズ計画＋3プラン比較表＋準委任・免責定義）」 |
| **`audit_scorecard.json`** | 100点満点スコアカード、6領域別得点、組織構造（Topology Map）の機械可読データ |
| **`summary.md`** | 全体の包括監査レポート（100点満点採点表＋組織構造＋弱点一覧＋3つの確認視点） |
| **`findings/WH-001.md`** | 弱点1件ごとの詳細ファイル（3軸リスク優先度 `1〜125`・何が起きるか・再現手順・修正パッチ例） |
| **`vulnerabilities.json`** | AIエージェントが読み取って自動修正するためのデータ一覧 |
| **`run.json`** | 最後まで終わったか（`completed` / `stopped`）と費用・検査範囲の記録 |

## ⚠️ 使うとき・クライアントへ提案するときの3大原則（必読）

1. **必ず「自分のアプリ」または「書面で許可をもらった対象」だけに使うこと**
   他人のWebサイトや許可のない取引先サイトを無断で調べることは法律違反（不正アクセス禁止法など）になります。このツールは安全のため、外部の無断URL（`https://...`）を指定すると自動でブロックする仕組みが入っています。
2. **本番環境ではなく、手元のパソコンや検証環境（ステージング環境）で行うこと**
   実際のお客様データや本番パスワードを置いた環境への直接負荷テストは避け、隔離された検証環境で実施してください。
3. **「100点・0件＝永久に100%無事故」ではないこと（準委任契約と3視点の開示）**
   単発の診断で100点になっても、翌週のAI機能追加や外部ライブラリの脆弱性発覚でスコアは再び低下します。また、クライアントへ継続保守を提案する際は「100%無事故の結果保証（請負）」ではなく**「善管注意義務に基づく継続的監査・是正伴走（準委任契約）」**とし、レポート末尾の **3つの視点（①完走確認、②上限停止の有無、③未検証の死角）** を必ず共有してください。
